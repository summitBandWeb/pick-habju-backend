## 2. 원인 분류별 상세 분석

### 2-1. CHECK 1: max_capacity=100 잔존 (23건) — 설계 의도

**원인**: `MANUAL_REVIEW_FLAG = 100`은 파서가 인원수를 추출하지 못했을 때 의도적으로 설정하는 플래그.

**설정 경로** (`room_collection_service.py`):
- `_extract_capacity_text_signals()`에서 텍스트 신호 추출 실패
- `room_parser_service.py`에서 구조화 파싱도 실패
- 둘 다 None → `MANUAL_REVIEW_FLAG(100)` 할당

**23건의 특성**:
- 14개 business에 분산 (1~3건씩)
- 주로 피아노 연습실, 보컬 연습실 등 **인원수 정보가 설명에 없는** room
- 대표 사례: `Studio.A 그랜드피아노`, `보컬/악기 연습실`, `일반피아노연습실1`

**결론**: 파싱 버그가 아닌 **데이터 부재**. 네이버 예약 설명에 인원수 정보가 없어서 추출 불가능. 수동 검토 후 적절한 값으로 교체하거나, 가격 기반 기본값 할당 로직 도입 필요.

### 2-2. CHECK 6: price_config 백필 누락 (47건) — 파서 한계

**원인**: `price_config`는 설명에서 시간대별 가격 패턴(`N시 이후 M원`) 또는 추가요금 패턴(`M원 추가`)이 있을 때만 설정됨.

**47건 분해**:
- CHECK 1과 겹치는 건: **23건** (max_capacity=100인 room은 대부분 price_config도 없음)
- 순수 CHECK 6만: **24건** (인원수는 파악됐지만 가격 구조 정보가 없는 room)

**원인 상세**:
1. **설명에 가격 구조 정보 부재** (~45건): 단순 시간당 가격만 있고, 시간대별/인원별 차등 요금 없음
2. **신규 수집 room** (~2건): 기존 DB에 없던 항목으로 기존값 보존 불가
3. **파서 패턴 미매칭**: 가격 정보가 있지만 파서의 정규식과 다른 형태

**결론**: 대부분 **네이버 예약 설명에 가격 구조 정보 자체가 없는** 케이스. `price_per_hour`만 있고 시간대별/추가요금 정보가 없으면 `price_config = NULL`은 정상 동작. **spec 재정의 필요**: "price_per_hour > 0이면 최소한 기본 price_config를 생성" vs "가격 구조 정보 없으면 NULL 허용".

### 2-3. CHECK 7: 안내성 문구 혼입 (2건) — 이름 정제 미흡

| biz_item_id | name | 문제 |
|-------------|------|------|
| 7480428 | `3월 이벤트 할인 예약` | "이벤트"+"예약" 패턴. 실제 room이 아닌 프로모션 예약 상품 |
| 6647355 | `밴드공연 .교회수련회 음향장비 셀프견적.예약금외 결제` | "견적" 패턴. 견적용 더미 상품 |

**원인**: 네이버 예약에 실제 room이 아닌 **프로모션/견적용 상품**이 등록됨. 현재 이름 정제 파이프라인은 프로모션 태그(`[특가]` 등)는 제거하지만, **상품 자체가 비룸인 경우**는 필터링하지 않음.

**결론**: `_should_exclude_room()` 필터 강화 필요 — "이벤트.*예약", "견적", "결제" 등의 패턴을 제외 조건에 추가.

### 2-4. CHECK A: Soft 키워드 (2건) — 정상

| biz_item_id | name | business_id | keyword |
|-------------|------|-------------|---------|
| 5392389 | `합주실 / 녹음실` | 706413 | 녹음 |
| 7454479 | `레코딩룸` | 247786 | 레코딩 |

**원인**: 합주실 business에 속한 부속 room. 합주 + 녹음 복합 공간은 실제로 존재.

**결론**: 정상 데이터. Soft 키워드는 합주실 business 소속이면 허용하는 현행 로직이 올바름.

### 2-5. CHECK C: 이름에 가격 정보 잔존 (2건) — 이름 정제 미흡

| biz_item_id | name |
|-------------|------|
| 6686059 | `[ 합주실A] 가격인하 10%~20% 평일,주말 차등요금` |
| 6686062 | `[합주실 B] 가격인하 10%~20% 평일 주말 차등요금` |

**원인**: 이름 정제 5단계 파이프라인 중 `_strip_promotional_tags()`는 `[특가]`, `[할인]` 등 대괄호 태그만 제거. 대괄호 밖의 "가격인하 10%~20%" 문구는 제거 대상이 아님.

**결론**: 이름 정제 규칙 확장 필요 — "가격인하", "할인", "%"가 포함된 접미사 제거 패턴 추가.

## 4. 이전 크롤링 잔재 vs 현재 파싱 버그

- **이전 크롤링 잔재**: 발견되지 않음. 이번 크롤링으로 데이터가 갱신되면서 이전의 잘못된 데이터는 대부분 교정됨.
- **현재 파싱 버그**: 직접적인 파싱 버그 없음. CHECK 7의 2건은 **필터링 규칙 부재**(버그가 아닌 미구현).
- **설계 한계**: CHECK 1(23건), CHECK 6(47건)은 원본 데이터에 해당 정보가 없어서 발생. 버그가 아닌 한계.

## 5. 권장 조치 (우선순위순)

### P1: CHECK 7 — 비룸 상품 필터 추가
- `_should_exclude_room()`에 안내성/견적/프로모션 상품 제외 패턴 추가
- 영향: 2건 제거 → 위반 2건 감소

### P2: CHECK C — 이름 정제 규칙 확장
- 가격 관련 접미사 제거 (`가격인하 N%`, `할인`, `차등요금` 등)
- 영향: 2건 개선 → 참고 2건 감소

### P3: CHECK 1 — max_capacity 기본값 전략 수립
- 현재: 파싱 실패 시 무조건 100(수동검토 플래그)
- 개선안: 가격대별 기본값 할당 (spec에 이미 정의됨: 10k-15k→8명, 15k-20k→11명, 20k+→15명)
- 영향: 23건 개선 가능

### P4: CHECK 6 — price_config spec 재정의
- 가격 구조 정보가 없는 room에 대해 NULL 허용 여부 결정
- 옵션 A: NULL 허용 (현행 유지, spec에서 이 CHECK 완화)
- 옵션 B: 기본 price_config 생성 (`{ base_price: price_per_hour }`)
- 영향: 47건 (spec 재정의에 따라 위반 건수 변동)
